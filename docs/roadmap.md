# Roadmap

This roadmap converts the source strategy into implementation milestones. It follows the phased build order defined in [OSINT_Lead_Gen_30_60_90_120_Day_Build_Plan.md](/Users/hifi/Downloads/Public_OSINT_Lead_Gen/OSINT_Lead_Gen_30_60_90_120_Day_Build_Plan.md).

## Day 0-30

Objective: launch a credible public OSINT hub and a repeatable publishing and capture loop.

Ship:

- public site with homepage, hub page, explainer, archive, and CTA
- source map with 10-20 public sources
- ingestion pipeline v1 with 3-5 collectors
- normalized storage
- first three weekly updates
- contact form and CRM sync
- analytics dashboard
- runnable web shell
- ingestion smoke workflow

Exit criteria:

- site is live
- daily ingestion is automated
- at least 3 updates are published
- lead capture works end to end
- a weekly update can be produced in under 90 minutes

Backlog: [day-0-30](/Users/hifi/Downloads/Public_OSINT_Lead_Gen/docs/issues/day-0-30.md)

## Day 31-60

Objective: qualify inbound interest with gated sharper signal.

Ship:

- gated insight layer
- historical charts
- CSV export
- nowcast v1
- lead scoring
- nurture sequence
- community signal intake and moderation
- distribution operating cadence
- gated insights page and form prototype

Exit criteria:

- gated asset is collecting qualified leads
- all leads are scored in CRM
- at least one inbound demo per week references updates
- at least five community submissions are reviewed

Backlog: [day-31-60](/Users/hifi/Downloads/Public_OSINT_Lead_Gen/docs/issues/day-31-60.md)

## Day 61-90

Objective: convert trust into revenue by productizing the execution layer.

Ship:

- paid pilot offer
- intake and triage workflow
- internal dashboard or API for execution support
- billing and contract workflow
- KPI dashboard for client work
- first pilot case studies

Exit criteria:

- paid pilot offer is live
- at least one client has paid
- time-to-first-recommendation is measurable
- one usable pilot narrative exists for sales

Backlog: [day-61-90](/Users/hifi/Downloads/Public_OSINT_Lead_Gen/docs/issues/day-61-90.md)

## Day 91-120

Objective: stabilize operations and prepare API or white-label expansion without overbuilding.

Ship:

- SOP library
- cleaned data model
- internal API schema
- pricing architecture
- beta partner requirements capture
- expansion scorecard

Exit criteria:

- publishing and lead-gen workflows are documented
- service delivery is repeatable
- API or white-label requirements are clear
- expansion decision criteria are explicit

Backlog: [day-91-120](/Users/hifi/Downloads/Public_OSINT_Lead_Gen/docs/issues/day-91-120.md)

## Strategic Guardrails

- Do not build multi-crisis abstractions before one wedge converts.
- Do not build heavy ML infrastructure before heuristic models stop being sufficient.
- Do not build public APIs before internal execution workflows are stable.
- Do not warehouse data unless reporting needs exceed the operational database.
