# Community Signal Moderation

## Goal

Accept useful external observations without polluting the signal quality of the public product.

## Intake Rules

- accept anonymous submissions
- require description of the observed issue
- require corridor, partner, or workflow context if available
- treat all submissions as unverified until reviewed

## Moderation States

- `new`
- `needs_evidence`
- `corroborated`
- `rejected`
- `published`

## Publish Standard

- do not publish any community signal without corroboration
- if corroboration is partial, describe it as observational rather than confirmed
- never turn anecdote directly into operator guidance
